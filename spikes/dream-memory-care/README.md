# Dream memory care: bounded local proof

76c's first slice exercises normal Markdown editing, a limited Git repository
with one care worktree, the existing memory linter and an ordinary Git diff.
It does not modify or install Dream runtime code. It starts no curator and
does not qualify a scheduled night. The configured visible curator remains
the existing owner; no model/session/account replacement is implemented here.

```sh
node spikes/dream-memory-care/proof.mjs SOURCE_WORKSPACE NEW_PRIVATE_OUTPUT
```

The input is deliberately limited to `MEMORY.md` and
`memory/references/memory-flow.md`. The proof splits dated history into
`memory-flow-history.md`, retaining the exact moved bytes and the old heading
anchors, and updates the index. Private content is stored only beneath the
explicit private output, never in this source repository or a remote.
The source workspace is read, never published to. The local intake/care
repositories have no remotes. The script refuses an existing output rather
than silently replacing its prior proof.

The existing full-memory guard is RED when a separate process writes an
unrelated reference/day heading. The intended Git patch applies to the local
intake while preserving those writes. A conflicting changed hunk refuses
`git apply --check` and leaves the care draft intact. A missing-link care
failure is detected by the existing linter while a separately valid synthetic
digest remains accepted by the existing product reader. That is a separation
proof, not evidence that the installed controller already handles the failure.

Lint runs before and after on the limited copy. Out-of-scope targets and the
reference template are absent, so their findings are retained explicitly;
this is zero *new* warnings, not a claim that the complete source is lint-clean.
An unchanged moved paragraph's warning is compared using its original file
attribution. Full findings and the exact private diff remain in the output.
Exact byte movement proves preservation for this move; lint cannot establish
the factual truth of arbitrary future rewrites.

## Remaining boundary

The worktree/current directory is **not an OS security boundary**. No untrusted
model was executed with these permissions. A future runtime slice must bind
the same configured visible curator to an ordinary fixed permission surface,
keep raw journals/credentials/original receipts outside its writable area,
and connect ordinary edits to the controller's existing digest result path.
An existing unknown submit must remain fenced; this proof does not read,
cancel, resend or reclassify queued jobs.

Publishing to shared memory also needs the existing owner/locking contract
and a recoverable multi-file application boundary. `git apply --check` plus
`git apply` is not an atomic concurrent publisher: a writer could intervene
between them. This proof qualifies the local editing/validation contract only.
No new per-run launch state machine, new repair language, timer, model call,
historical import, automatic push or independent review gate is introduced.
